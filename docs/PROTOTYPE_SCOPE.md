# UI prototype scope

## Product assumptions

- Target: Flutter desktop for Windows 10/11.
- Source system: classic Medialog 7.
- Current delivery: visual prototype only, with synthetic data.
- Future document generation: CDA/XML generated by this application from mapped Medialog 7 data.
- Planned signature flow: clinician qualified electronic signature plus medical organization signature.
- Submission mode: semi-automatic, with operator review and explicit send action.

## Screens

1. Dashboard: counters, readiness summary, recent documents, activity.
2. Preflight: FRMO, FRMR, clinician certificate, organization certificate, signing-time validation, CDA validation.
3. Queue: search, filters, document status, document details.
4. Archive: structured source, PDF rendition, signatures, original N3 response, readable response report, validation report.
5. Audit: operator and system actions.
6. Settings: Medialog, N3.Health, cryptography, organization, templates, archive, automation.

## Non-goals for this prototype

No real patient data, database connections, N3.Health requests, FRMO/FRMR lookups, certificate access, cryptographic operations, or file archive writes are implemented.

All displayed identities, identifiers, dates, counters, and statuses are synthetic. Do not use this build for clinical or production workflows.

## Architecture direction

Keep UI presentation separate from future integrations. Planned boundaries:

- MedialogRepository: read-only extraction from Medialog 7.
- SemdBuilder: build CDA/XML from mapped source data.
- PreflightService: FRMO/FRMR, certificate, signing-time, and CDA checks.
- SignatureService: CMS signing and verification through approved Windows cryptographic components.
- N3HealthClient: N3.Health service communication.
- SubmissionQueue: idempotent semi-automatic send orchestration.
- ArchiveRepository: immutable source artifacts and response snapshots.
- AuditRepository: append-only audit events.

Production implementation must be based on the current N3.Health integration contract and the medical organization's approved security model.
