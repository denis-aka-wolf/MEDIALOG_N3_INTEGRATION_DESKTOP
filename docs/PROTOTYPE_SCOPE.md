# Объём визуального прототипа

## Исходные предположения

- Целевая платформа: настольное приложение Flutter для Windows 10/11.
- Исходная система: классическая Медиалог 7.
- Текущий результат: только визуальный прототип с вымышленными демонстрационными данными.
- Планируемое формирование документов: приложение самостоятельно формирует CDA/XML на основании сопоставленных данных Медиалог 7.
- Планируемая схема подписания: усиленная квалифицированная электронная подпись (УКЭП) врача и отдельная УКЭП медицинской организации.
- Режим передачи: полуавтоматический. Оператор проверяет подготовленный документ и явно подтверждает его отправку.

## Разделы приложения

1. Панель управления: счётчики, сводка готовности, последние документы и активность.
2. Предварительный контроль: ФРМО, ФРМР, сертификат врача, сертификат медицинской организации, проверка времени подписания и валидация CDA.
3. Очередь: поиск, фильтры, статусы документов и просмотр сведений о документе.
4. Архив: исходный структурированный документ, PDF-представление, подписи, исходный ответ N3.Health, читаемый отчёт об ответе и отчёт о проверках.
5. Журнал действий: операции оператора и системные события.
6. Настройки: Медиалог 7, N3.Health, криптография, медицинская организация, шаблоны, архив и автоматизация.
7. ИЭМК пациентов: реестр пациентов, демонстрационная карточка пациента, медицинская история, документы СЭМД, направления и сопоставление записей.
8. Управление ЭЦП и сертификатами: реестр сертификатов врачей, медицинской организации и служебных сертификатов; поиск и фильтрация; карточка с серийным номером, отпечатком, контейнером, удостоверяющим центром и периодом действия; расчёт остатка срока; предупреждения об истёкших и истекающих сертификатах; демонстрационные статусы регистрации и отзыва.

## Что не входит в прототип

Не реализованы работа с реальными данными пациентов, подключение к базам данных, запросы к N3.Health, поиск сведений в ФРМО/ФРМР, чтение Windows Certificate Store, импорт и проверка реальных сертификатов, проверка CRL/OCSP, доступ к закрытым ключам, криптографические операции и запись файлов в настоящий архив. Реестр ЭЦП содержит только вымышленные демонстрационные записи; пересчёт сроков выполняется по встроенным тестовым датам.

Все отображаемые ФИО, идентификаторы, даты, счётчики и статусы являются вымышленными. Не используйте эту сборку в клинических или производственных процессах.

## Направление архитектуры

Представление пользовательского интерфейса необходимо отделить от будущих интеграционных компонентов. Планируемые границы ответственности:

- `MedialogRepository`: извлечение данных из Медиалог 7 только для чтения.
- `SemdBuilder`: формирование CDA/XML на основании сопоставленных исходных данных.
- `PreflightService`: проверки ФРМО/ФРМР, сертификатов, времени подписания и CDA.
- `CertificateRepository`: чтение открытых атрибутов сертификатов из разрешённых хранилищ Windows без извлечения закрытых ключей.
- `CertificateStatusService`: проверка срока действия, цепочки доверия и статуса отзыва сертификата.
- `SignatureService`: подписание и проверка CMS с использованием утверждённых криптографических компонентов Windows.
- `N3HealthClient`: взаимодействие с сервисами N3.Health.
- `SubmissionQueue`: управление полуавтоматической отправкой с защитой от повторной обработки.
- `ArchiveRepository`: неизменяемое хранение исходных документов и снимков ответов.
- `AuditRepository`: добавление записей аудита без возможности их незаметного изменения.

Промышленная реализация должна опираться на действующий регламент интеграции N3.Health и утверждённую модель информационной безопасности медицинской организации.
